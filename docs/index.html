Why use Osien-Stack?

Because your AI is only as good as the tools it can reach. Osien-Stack gives every AI the same unfair advantage — memory, verification, parallel work, and context discipline — without you lifting a finger.

Remembers everything

ctx_recall / ctx_save split memory into 5 parts (architecture, decisions, failures, state, performance). Your AI never starts cold again.

Blazing fast

File cache (0.49ms/read), exec cache, trimmed prompts (−50% tokens), parallel batch ops. Answers land before you blink.

93% fewer tokens

read_slice, smart_grep and ctx_recall feed the model only what matters. Stop paying for whole-file reads.

Verifies before done

verify_chain, security_scan, test_gap, repro_capsule. No more "trust me, it works." Evidence or it didn't happen.

City Mode

14 AI agents with personalities (Mayor, Hammer, Detective, …) debate and review your work in parallel.

Works everywhere

opencode, Claude Code, Cursor, Cline, Windsurf — any MCP client. Degrades gracefully elsewhere.

How it works

One MCP server. Stdio transport. Any AI talks to it like a native tool. Your AI keeps its brain; Osien-Stack gives it hands.

1

AI fetches the repo

One prompt: "install osien-stack". The AI clones, runs npm install, wires the MCP server into its own config. Done.

2

Tools come online

45 tools register over stdio. Memory, verify, search, state, city mode — all callable by name.

3

AI uses them by default

Instructions (SITE LAW, TOOL-FIRST, PARALLELISM) are auto-loaded. The AI stops hand-rolling scripts and starts forging tools.

4

You ship faster

93% fewer tokens, 0.49ms cached reads, parallel batch ops. Same model, ten times the throughput.
